# Document analysis flow

1. `public/model.js` identifies PDF/image signatures, decodes UTF-8 text, or calls `/api/extract` for supported PDF/Office formats. There is no revenue-only upload filter.
2. `scripts/server.py` serves `public/` on loopback and extracts DOCX, XLSX, PPTX, and ODT in memory. It bounds compressed input, total uncompressed ZIP size, entry count, and extracted text size. It rejects XML DTD/entity declarations and cross-origin extraction requests. Office extraction is in memory; PDF extraction uses a temporary directory and `pdftotext` (up to 100 pages; larger PDFs are rejected) with cleanup. It does not execute macros or recalculate formulas. Scanned PDFs require conversion to text/images.
3. The browser holds up to five attachments. Changing the attachment set resets the conversation. Text previews are truncated only for display; the accepted full text is retained for inference.
4. Sending chat calls same-origin `/api/generate`. Python validates bounded document text/images, chat, and previous module/error context. It reads root `.env` at startup (process variables take precedence), keeps the API key server-side, and calls mainnet 0G Chat Completions with Private routing and JSON mode. Default model: `0gm-1.0-35b-a3b`. Output is capped at 6,000 tokens, provider timeout at 180 seconds, and concurrency at one run. When GEMINI_API_KEY is non-empty, a non-200 HTTP response triggers one Gemini attempt through Google’s OpenAI-compatible endpoint (default gemini-3.8-flash), capped at 16,384 tokens with a 60-second timeout. HTTP-200 validation failures, local validation/configuration errors, network timeouts, and compiler/runtime errors do not trigger fallback. The browser allows 280 seconds for generation.
5. The responding provider returns `{title, reply, source}`. `source` is a complete JavaScript JSX module with a default component export. The response is bounded to 200 KB of source. There is no predefined dashboard component menu.
6. The browser sends only the source to `POST /api/compile`. Python starts `scripts/compile.cjs` as a bounded-time Node process. esbuild parses/bundles React and JSX without executing the module. A resolver plugin permits only React imports from generated source and denies file paths, URLs, node builtins, and arbitrary npm dependencies. No generated dependencies are installed and no generated source is stored on disk. The server returns a self-contained JavaScript bundle.
7. The parent navigates an iframe to the fixed `preview.html`, with `sandbox="allow-scripts"` and no same-origin permission. A fixed bootstrap (`preview.js`) accepts one bundle from its parent and loads it through a temporary blob URL. The preview CSP blocks network connections, external assets, forms, objects, and base URL changes; inline styles and the bundled script are permitted. Raw attachments are never posted into the iframe. Any data embedded by 0G is naturally present in the generated module.
8. React mounts the default export inside an error boundary. Preview ready/runtime-error messages are accepted only from the current frame. Compile failure leaves the previous working frame intact. Follow-up generation receives failed source and the visible error so it can attempt a correction. React source is available in the source tab and as a JSX download. Exports contain the source and its embedded data, not the API key or raw attachment bytes.
9. Provider identity, original 0G HTTP status for fallback, finish reasons, token counts, and provider IDs remain in sanitized diagnostics. Compiler success/failure and runtime failure are separate entries correlated by the local request ID. Compiler error details are visible in chat; code and runtime error content are not written to the diagnostic log.

The sample monthly revenue parser and least-squares forecast remain as an optional local helper. They run only for forecast/prediction requests on a compatible CSV. ## Boundaries

This local prototype is not a shared authenticated service. It has no persistent document storage, tenant isolation, or production credential management. Browser sandboxing is not a full resource isolation system: generated infinite loops or extreme allocations can still degrade the browser. Server compilation is limited by input size and a subprocess timeout, not a production container sandbox. 0G receives the inference request using requested Private routing. The local backend sees plaintext; requesting Private routing does not independently verify attestation or make the whole app end-to-end encrypted. Optional Gemini fallback sends the same context to Google under its own data policy, without 0G private routing. Neither API key reaches the browser. Add user authentication, per-user limits, and stronger isolation before shared deployment. Do not expose the local server publicly.

0G reference: https://docs.0g.ai/developer-hub/building-on-0g/compute-network/overview

Receipts include provider request IDs and token usage. The UI estimates 0GM cost using current promotional rates; it does not read the account balance. Sanitized logs are written server-side to `.local-artifacts/inference.jsonl`, excluding prompts, files, keys, and source.
